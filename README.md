# Практическая работа 6. Адаптивная вёрстка, сборка, публикация и тестирование

Магазин кроссовок на Flutter Web. Продолжение ПР5: интерфейс приведён в
работоспособный вид на экранах любой ширины, собрана и опубликована релизная
версия, работа покрыта модульными тестами и тестами виджетов.

- Опубликованное приложение: https://sedive666.github.io/pr6/
- Данные берутся с учебного сервера `api/mock-server.js`. Для работы
  опубликованной версии сервер запускается на том же компьютере, где открыт
  сайт: `node api/mock-server.js` (порт 8080). Без сервера приложение
  открывается и показывает сообщение о пропаже связи, а когда сервер
  поднимется — само догружает данные, без обновления страницы.
- Учебные записи: `admin/admin123`, `manager/manager123`, `client/client123`.

## Запуск

```bash
node api/mock-server.js --port 8080 --origin http://localhost:5555
flutter run -d chrome --web-port=5555
```

Проверки:

```bash
flutter analyze
dart format --set-exit-if-changed lib test
flutter test
```

## Адаптивная вёрстка

Все числа точек перелома лежат в одном месте — `lib/core/breakpoints.dart`;
виджеты спрашивают `layoutOf(width)`, а не сравнивают ширину сами.

| Ширина окна | Раскладка  | Что видно |
| --- | --- | --- |
| до 600 | `compact` | одна колонка, навигация снизу, списки карточками |
| 600–1023 | `medium` | боковая полоса со значками, карточки в две колонки |
| 1024–1439 | `expanded` | таблицы, боковая полоса с подписями |
| 1440 и шире | `large` | то же, содержимое ограничено 1400 пикселями по центру |

Окно меняется мышью во время работы приложения: раскладка перестраивается
без перезагрузки, консоль браузера чистая.

Что сделано в этой работе:

- навигация перестроена: вместо одной ленты значков на всех ширинах —
  `NavigationBar` снизу на узком окне (четыре раздела плюс пункт «Ещё» с
  остальными), `NavigationRail` со значками на среднем и развёрнутый rail с
  подписями на широком (`lib/widgets/app_scaffold.dart`);
- таблица получила настоящую двумерную прокрутку с двумя видимыми полосами, а
  высоту ей задаёт родитель, поэтому прокручивается таблица, а не вся
  страница (`lib/widgets/entity_table.dart`);
- до 1024 таблица заменяется карточками, на 600–1023 они раскладываются в две
  колонки (`lib/widgets/entity_card_list.dart`);
- длинные значения в таблицах и заголовки карточек обрезаются многоточием
  (помощник `cell()` в `entity_table.dart`), раньше описание категории или
  список категорий модели растягивали таблицу;
- имя пользователя в шапке ограничено по ширине и обрезается, на узком окне
  уходит в подсказку кнопки выхода;
- диалоги подтверждения ограничены шириной 420 пикселей;
- в карточке записи на узком окне метка и значение идут друг под другом, а не
  в две колонки с жёсткими 170 пикселями;
- исправлено переполнение строки пагинации на ширине 360: кнопки уплотнены,
  подпись страницы сжимаема (`lib/widgets/list_controls.dart`);
- формы по-прежнему ограничены шириной 640, панели отбора построены на `Wrap`.

## Работа при недоступном сервере

`lib/core/connectivity.dart` — `ConnectivityMonitor`. О пропаже связи сообщает
интерсептор сетевого слоя; пока связи нет, монитор сам опрашивает
`GET /__health` раз в три секунды. Первый успешный ответ переводит его в
состояние «на связи» и оповещает слушателей — списки и экраны личного кабинета
перезагружают данные сами. Пока связи нет, сверху видна полоса с объяснением.
Страницу обновлять не нужно.

Заодно исправлено: после ошибки повторный переход по тому же адресу не
перезагружал список, потому что `ListNotifier.applyQuery` выходил раньше при
неизменённом запросе.

## Доступность

- у всех значков без подписи есть подсказка, включая показ пароля;
- `Semantics` у переключателя доступа, флажка выбора записи, значков состояния
  и правил пароля;
- первое поле формы получает фокус при открытии, Enter переходит к следующему
  полю, а в последнем отправляет форму;
- порядок обхода Tab внутри формы задан `FocusTraversalGroup`.

## Сборка

Адрес API в исходном коде не записан: `lib/core/config.dart` читает его только
из параметра сборки `String.fromEnvironment('API_BASE_URL')`.

Релизная сборка и локальная проверка:

```bash
flutter build web --release --dart-define=API_BASE_URL=http://localhost:8080/api
py tools/serve.py 5555 build/web
```

`tools/serve.py` отдаёт `index.html` на любой неизвестный путь, поэтому
обновление страницы на внутреннем экране не даёт 404; ответы сжимаются gzip,
как на хостинге.

Сборка для публикации в подкаталоге:

```bash
flutter build web --release --base-href /pr6/ \
  --dart-define=API_BASE_URL=http://localhost:8080/api
cp build/web/index.html build/web/404.html
```

Флаги: `--release` — оптимизированная сборка без отладочного кода;
`--base-href /pr6/` — базовый путь, без него браузер запрашивал бы
`main.dart.js` из корня домена и показывал белый экран; `--dart-define` —
адрес сервера. Вариант на WebAssembly собирается флагом `--wasm`, в каталоге
оказываются оба варианта: `main.dart.wasm` и `main.dart.js`.

## Публикация

Публикацию выполняет GitHub Actions при каждом изменении ветки `main`:
проверки, тесты, сборка, копия `404.html` и выкладка на GitHub Pages. Если
анализатор, форматирование или тесты не прошли, публикации не будет. Файл
настройки — `.github/workflows/deploy.yml`.

Настройки хостинга:

- **Settings → Pages → Source: GitHub Actions** — сайт выкладывается из
  артефакта сборки, отдельная ветка `gh-pages` не нужна.
- **Базовый путь.** Сайт открывается по адресу `sedive666.github.io/pr6/`, а
  не из корня домена, поэтому сборка идёт с `--base-href /pr6/` (в файле
  настройки — по имени репозитория).
- **Прямые ссылки.** Адреса без решётки (`/sneakers/1`) разбирает приложение,
  а GitHub Pages ищет такой файл на диске. Перенаправлять неизвестные пути на
  `index.html` он не умеет, но отдаёт `404.html` — поэтому она сделана копией
  `index.html`. Приложение загружается, разбирает адрес и открывает нужный
  экран.
- **Адрес API.** Pages работает только по HTTPS, а учебный сервер — по HTTP.
  Обращение со страницы HTTPS к произвольному адресу HTTP браузер блокирует
  как смешанное содержимое, но `localhost` считается доверенным источником,
  поэтому опубликованная сборка обращается к `http://localhost:8080/api`.
  Сервер разрешает запросы с любого источника (параметр `--origin`, по
  умолчанию `*`).

## Размер сборки и время первой загрузки

Замер выполнен скриптом `tools/measure.mjs` в Chrome с отключённым кэшем,
сеть ограничена 10 Мбит/с с задержкой 40 мс, файлы отдаёт `tools/serve.py` со
сжатием gzip. «Скачано при входе» — сумма `encodedDataLength` всех запросов,
«первая загрузка» — от начала навигации до события `flutter-first-frame`,
медиана пяти прогонов.

| Сборка | Каталог | Код приложения | Скачано при входе | Первая загрузка |
| --- | --- | --- | --- | --- |
| Обычная | 31 МБ | `main.dart.js` 2856 КБ | 1,64 МБ | 1,96 с |
| С `--wasm` | 33 МБ | `main.dart.wasm` 2588 КБ и `main.dart.js` 2856 КБ | 1,19 МБ | 1,46 с |
| После оптимизации | 31 МБ | `main.dart.js` 2825 КБ и 6 частей по требованию (48 КБ) | — | — |

Бо́льшую часть каталога занимает движок отрисовки (`canvaskit`, несколько
вариантов по 3–7 МБ); браузер скачивает только один из них, поэтому на объём
загрузки влияет прежде всего код приложения: в сжатом виде `main.dart.js` —
840 КБ, то есть около половины всего, что скачивается при входе.

Вариант `--wasm` занимает на диске больше, потому что содержит обе сборки, но
браузер с поддержкой WasmGC скачивает меньше (1,19 МБ против 1,64 МБ) и
запускается быстрее. Браузер без WasmGC (Safari) загружает вариант на
JavaScript.

Размер уменьшен двумя изменениями: редко открываемые разделы (личный кабинет,
пользователи, статистика, справочники, покупатели, заказы, отзывы) подключены
в маршрутизаторе через `import … deferred as` и скачиваются отдельными частями
при первом открытии; удалён неиспользуемый пакет `cupertino_icons`. Выигрыш
скромный — экраны тонкие, а общая машинерия списков и форм остаётся в основной
части; настоящее сокращение загрузки даёт вариант на WebAssembly.

| Тест | Что проверяет |

## Слои

```
screens → widgets → state (ListNotifier, AuthNotifier) → repositories → core (Dio) → сервер
```

| Слой | Содержимое |
| --- | --- |
| `core` | `breakpoints.dart` — точки перелома; `connectivity.dart` — монитор связи; `config.dart`, `api_client.dart`, `api_exceptions.dart`, `permissions.dart`, `auth_api.dart` |
| `models` | сущности с `toJson`/`fromJson`, `PageResult<T>`, условия отбора, валидаторы |
| `repositories` | `EntityRepository<T, Q>` и реализация `ApiRepository<T, Q>` |
| `state` | `ListNotifier<T, Q>`, `AuthNotifier` |
| `widgets` | `EntityTable<T>`, `EntityCardList<T>`, `EntityListView<T, Q>`, `EntityFormScreen`, `AppScaffold`, `DeferredScreen` |
| `screens` | экраны сущностей: только описание колонок и полей формы |
| `api` | учебный сервер `mock-server.js` и контракт `КОНТРАКТ-API.md` |
